Техническое задание: Система управления услугами барбершопа

1. Проектирование модели данных и жизненных циклов (State Modeling)

Разработана статусная модель для ключевых сущностей системы. Для всех объектов, имеющих жизненный цикл, введен атрибут «Статус» и определена логика переходов.

1.1. Жизненный цикл «Слота обслуживания» (Appointment):

Разработана диаграмма состояний (State Diagram), покрывающая полный цикл от создания слота до выполнения услуги.

Определены статусы: Создан, Забронирован, В работе, Выполнен, Отменен (клиентом), Отменен (барбершопом).

Прописаны условия переходов, инициаторы (роли) и автоматические действия системы при смене статуса.

Актуализированы сценарии использования (Use Cases) с учетом смены статусов.

1.2. Жизненный цикл прочих сущностей:

Определены статусные модели для справочных сущностей (Клиенты, Сотрудники, Услуги).

Для каждого перехода зафиксированы: исходное/целевое состояние, событие-триггер, необходимые проверки и постусловия.

2. Управление справочниками (Master Data Management)

Спроектирована функциональность для работы со справочниками: Клиенты, Сотрудники, Роли сотрудников, Услуги, Услуги мастера.

Операции: Полный цикл CRUD (создание, чтение, редактирование, удаление).

Логика:

Определены условия выполнения операций и валидация данных.

Описаны триггеры: изменения в смежных системах, логирование действий, отправка уведомлений заинтересованным лицам.

Введена связь операций с соответствующими Use Cases.

3. Функциональные требования к работе со слотами (Booking Management)

Детализированы требования к интерфейсу и логике работы с основным объектом системы — «Слот обслуживания».

Представление: Поддержка отображения в виде списка и карточки.

Инструменты работы с данными:

Фильтрация, сортировка и поиск записей.

Механизмы подтверждения критичных операций и их откат.

Аудит: Обязательное логирование всех операций и изменений состояний.

4. Ролевая модель и безопасность (RBAC)

Разработана матрица доступа (CRUD-матрица) для ролей: Администратор, Менеджер, Мастер, Клиент.

Разграничение прав: Четко определены права доступа каждой роли к объектам (Слоты, Клиенты, Сотрудники, Услуги).

Условия доступа: Прописаны бизнес-правила, ограничивающие выполнение операций (например, доступ только к своим записям).

Политика удаления данных:

Введен запрет на физическое удаление данных для большинства ролей.

Исключение: Удаление разрешено только роли «Администратор» и только для записей, неактивных более 1 года (архивация/очистка).
